# Agent Scorers

MUSEは [Mastra Evals](https://mastra.ai/) のスコアラーフレームワークを使って、エージェントの出力を自動的に採点します。スコアラーはエージェント定義に直接配線され、実行結果はトレースと一緒に記録されるため、別途評価用のハーネスを用意せずに品質の傾向を追跡できます。

このページでは、MUSEで採用しているスコアラーパターンと、結果をローカルで確認する方法を説明します。

## MUSEにおけるスコアラーパターン

スコアラーはエージェントに紐付けられた小さな評価器です。エージェントが出力を生成すると、Mastraは1つ以上のスコアラーを実行し、常時（サンプリング比率1.0）または一部の実行のみ（部分サンプリング）採点を行います。スコアはトレースとともに保存されます。

2種類のスコアラーが使われています。

- **Code scorers** — TypeScriptで書かれた決定論的なチェック（LLM呼び出しなし）。コストが低いため、毎トレース実行できます
- **LLM scorers** — 評価用モデルがエージェントの入力・出力・システムプロンプトを読み、根拠つきの数値スコアを返します。コストが高いため、部分サンプリングで実行されます

## Recipeエージェントに配線されたスコアラー

[測定レシピ](../user-guide/recipe.md) エージェントは代表的な例で、3種類のスコアラーを持っています。

| スコアラー | 種類 | サンプリング | 検査内容 |
|-----------|------|-------------|---------|
| **toolCallAccuracy** | Code | 1.0（毎回） | エージェントが期待されたツール（`recipeTool`）をstrictモードで呼び出したか。ワークフローが依存する *エージェント → ツール* 契約を強制する |
| **promptAlignment** | LLM | 0.3 | 出力がシステムプロンプトの指示に整合しているか（`evaluationMode: "system"` として評価） |
| **answerRelevancy** | LLM | 0.3 | 出力が入力リクエストに対して関連性を持っているか |

2つの設計判断が特に重要です。

- **Tool-call accuracyは毎トレース実行される** — これは強い契約を強制するためです。RecipeエージェントがrecipeToolを呼ばなくなるとワークフロー全体がエラーになるため、リグレッションを即座に捕捉することにわずかなコストを払う価値があります
- **LLMスコアラーは30%サンプリング** — LLM呼び出しコストがかかるため、システミックなドリフトを捕捉するには30%で十分と判断されています

## スコアラー結果の確認

スコアラーの結果はMastra Studioで確認できます。museの開発スタックに同梱されています。

museリポジトリからMastra開発サーバーを起動：

```bash
cd muse
bun dev:mastra
```

Studioは `http://localhost:4111` でホストされます。エージェントの任意のトレースを開くと、トレース詳細にスコアラー結果が表示されます — スコア値、サンプリングフラグ、そして（LLMスコアラーの場合は）評価用モデルが返した根拠。

:::info ストレージについて
スコアラー結果はMastraのLibSQLストレージ経由で永続化されます — トレースと同じストアです。Vercelでは、ストレージURLは一時的な実行のため `:memory:` にフォールバックします（museリポジトリの `mastra/index.ts:41` を参照）。ローカルではmuseプロジェクトの隣にある `mastra.db` に結果が保存されます。
:::

## スコアラーの追加・変更

スコアラーはエージェントごとに `muse/mastra/agents/*.ts` で定義されています。代表例は `recipe-agent.ts` で、3種のスコアラーをエージェントの `scorers: { ... }` ブロックに配線しています。新しいスコアラーは `mastra/scorers/index.ts` に置き、ランタイムに拾わせるためにエクスポートされる `SCORERS` マップに追加する必要があります。

事前定義済みスコアラーの一覧は `@mastra/evals/scorers/prebuilt` に用意されています。現行の一覧と期待される入力は、Mastra Evals公式ドキュメントを参照してください。

:::warning ユーザー向け機能ではありません
スコアラー結果はエンジニアリング用のテレメトリです — MUSEのUIには表示されず、エンドユーザー向けではありません。目的は、エージェントの挙動が退行したときに、チームに速く安価なシグナルを届けることです。
:::
